Bookshelf Benchmark

Can AI chat models read a bookshelf? We gave Claude, Gemini and GPT the same six real bookshelf photos and asked them to list every book whose title they could read, then checked their answers against a hand-verified list.

Show the numbers as a table
  • Input: the prompt plus the six photos, using each provider's image-token rule (Claude: up to about 4,800 tokens per large photo; Gemini: 1,120 per photo; GPT: one token per 32×32 patch of the image as ChatGPT stored it).
  • Output: the saved reply, plus thinking. The apps hide the thinking itself. For Claude, the chat data records how long it thought, and that time is multiplied by the speed at which the same run wrote its reply. For Gemini, it's the extra time over the standard run of the same model.
  • ChatGPT: even in standard mode it ran Python OCR on the photos in a loop (12–15 model turns), re-reading the images each turn, and its "Think" mode was served by a different model (gpt-5-6-t-mini). Its hidden reasoning is unknown, so its range is the widest. Both GPT modes are priced at the GPT-5.6 Luna rate.
  • Hidden system prompts added by the apps are not counted. Treat the costs as rough: good for comparing orders of magnitude, not cents.

What we found

  1. Precision is high almost everywhere; recall is what separates the models. When a model names a book, it is nearly always really there. The difference is how many of the books each model manages to list.
  2. Claude reads crowded shelves far better. On the two hard photos, every Claude setup found more books than every Gemini and GPT setup. With one photo per chat, even the weakest Claude run found about twice as many as the best Gemini run.
  3. Gemini 3.8 Flash is best on the easy shelves. On the two easy photos it scored higher than every other model, including all the Claude runs.
  4. Sending six photos at once held Claude back. With one photo per chat, every Claude run found at least as many books, and Claude Opus 5.5 at low effort caught up with Opus 5.5 at high effort.
  5. One run per setting isn't enough. Repeating experiment 1 a week later moved some scores a lot: Opus 5.5 at low effort went from F1 0.72 to 0.87, close to its high-effort score (0.89). Most setups moved by 0.01–0.10. Claude still came out on top and GPT at the bottom.
  6. Extra effort pays off unevenly. For Opus 5.5, Gemini 3.1 Pro and GPT, the higher setting added only about 0.01–0.02 F1 while costing 1.3–1.7× as much. For Sonnet 5.5 (+0.10) and Gemini 3.8 Flash (+0.08, at about 5× the cost) it made a real difference.
  7. Cost and accuracy go together across providers. The cheapest setups (GPT and Gemini, about $0.02–0.09 per run) were also the least accurate. The most accurate, Opus 5.5, cost about $0.17–0.31; Opus 5 cost more than Opus 5.5 and scored lower.
  8. Gemini's limit is how well it reads, not the batching. Sent one hard photo at a time, Gemini still listed about the same number of books. It just named fewer wrong ones.
  9. Newer models improved. Opus 5.5 beat Opus 5, and Sonnet 5.5 beat Sonnet 5 by a wide margin, at the same effort.

Model vs harness: same model, very different result

The answer key itself was built with Claude Opus 5.5, the same model that scored best here, and together with a person it found nearly every readable book. Yet in a single chat, Opus 5.5 at high effort found about 77% of the books on the hardest photo. The model was the same; what changed was how it was used.

Building the answer keyA single chat
Image detailFull-resolution originals, cropped into small regions and enlargedThe whole photo at once; chat apps usually shrink large images before the model sees them
PassesOver a hundred zoomed crops, shelf by shelf, some rotated so spines read uprightOne look at the whole shelf
TaskCheck and extend an existing listList everything from scratch
CheckingA person confirmed every addition against a cropThe model alone, in one reply

The biggest factor is resolution: in a shrunk 24-megapixel photo, a spine title can end up only a few pixels tall and simply can't be read. Effort mattered less: in experiment 2, low effort matched high once the six-photo batching was removed. In other words, the surrounding system (zooming, multiple passes, verification) can matter more than the model or its settings.

Possible next experiments

  • A simple zoom harness: split each hard photo into overlapping full-resolution crops, ask the model about each crop, then merge the lists. This would measure how much of the gap is resolution alone. It needs API access rather than the chat apps.
  • Repeat runs: run each setup several times to see how much results vary from run to run.
  • Image compression: compare original, moderately and heavily compressed photos for accuracy and cost.
  • Other ways of packaging the photos: a ZIP, a PDF, or a document instead of separate images.

How it was measured

  • Answer key: six photos, 295 books, each confirmed by a person against a zoomed-in crop of the photo. Books too hard to read with confidence were left out.
  • Recall: of the books in the answer key, the share the model found. Precision: of the books the model named, the share that are in the answer key. F1 combines the two.
  • Matching: titles are matched approximately, so small differences in wording, punctuation, word order or a missing subtitle don't count as wrong.
  • "Not in the answer key" isn't always a mistake. Models sometimes found real books that were left out of the answer key because they were hard to confirm, so precision is slightly understated.
  • Setup: all runs used the normal consumer apps (ChatGPT, Claude.ai in incognito chats, Gemini). Experiment 1 was run twice; small differences between runs may be noise.
  • Run 2: a coding agent (Claude Code with the Claude in Chrome extension) drove the chat apps in the browser: it opened temporary chats, picked the model and mode, attached the photos, pasted the prompt and saved the reply exactly as written. It also read each app's own conversation data, which confirmed the model and setting used and gave thinking and reply timestamps for the cost estimate. Gemini 3.8 Flash with extended thinking failed once ("something went wrong") and was retried in a new chat.
  • Photo labels: the Claude app doesn't show the model the filenames, so Claude lettered the photos in a different order. Its lists were matched back to the right photos before scoring.
